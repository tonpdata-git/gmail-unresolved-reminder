# Gmail「未対応」5日超過通知

東北大学学友会報道部の共有Gmailで、「未対応」ラベルが付いたまま、最新の外部からの受信メールから5日以上たったスレッドを、部員へ毎日1通のまとめメールで知らせるGoogle Apps Scriptです。

制作は小宮正希（東北大学学友会報道部、GitHub: [@komiyamasakir7-max](https://github.com/komiyamasakir7-max)）です。報道部のウェブサイト [ton-press-web](https://github.com/tonpdata-git/ton-press-web) と同じく、部のアカウント `tonpdata-git` のもとで管理しています。

仕組みは報道部のGoogleアカウントの中だけで完結します。パスワード、OAuthトークン、APIキーは使いません。Claude、Codex、GitHub Actionsなどの外部サービスへGmailを接続する必要もありません。

## 重要な注意

- このリポジトリには、部員・取材先・共有メールの実アドレス、メール本文、認証情報を絶対にコミットしないでください。設定例はすべて `example.com` か `REPLACE_WITH_*` のプレースホルダーです。
- 実アドレスは、Apps Scriptのエディタへ貼り付けた後のコードにだけ入力します。
- トリガーは、作成したGoogleアカウントの権限で動きます。必ず報道部の共有Googleアカウントで作業してください（別のアカウントで本番を動かそうとすると、スクリプトが止めます）。
- Googleグループの共同トレイではなく、通常のGmail受信箱を前提にしています。

## 動作

1. Gmailの「未対応」ラベルが付いたスレッドを100件ずつ読みます（ゴミ箱・迷惑メールのスレッドは除きます）。
2. スレッドの中で、いちばん新しい「外部からの受信メール」の日時を基準にします。共有メール自身、`mailboxAddresses` に書いた別名、Gmailの「送信元」に登録済みの別名から送ったメッセージは、外部からの受信として数えません。下書きとゴミ箱に入れたメッセージも数えません。
3. 基準から24時間×5（120時間）以上たったスレッドを、受信の古い順に並べます。
4. 件名、送信者、受信日時、経過日数、Gmailへのリンクを1通のメールにまとめ、宛先ごとに個別に送ります（宛先同士にアドレスは見えません）。
5. 対象が0件の日は何も送りません。「未対応」ラベルを外したスレッドは、次の回から対象になりません。

## 導入手順

### 1. Apps Scriptプロジェクトを作る

1. 報道部の共有Googleアカウントでログインします。
2. <https://script.google.com/> を開き、「新しいプロジェクト」を作ります。
3. プロジェクト名を `報道部・未対応メール通知` などに変えます。
4. 「プロジェクトの設定」（歯車）でタイムゾーンを `(GMT+09:00) 日本標準時`（Asia/Tokyo）にします。「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにした場合は、[`appsscript.json`](./appsscript.json) の中身を貼り付けても同じです。
5. エディタの `コード.gs` の中身を消し、[`Code.gs`](./Code.gs) の全文を貼り付けて保存します。

### 2. 設定値を置き換える

`CONFIG` の次の項目を、Apps Scriptのエディタ上で書き換えます。

| 項目 | 内容 |
|---|---|
| `mailboxAddresses` | 報道部の共有メールアドレス。返信に使う別名があればすべて追加します。 |
| `testRecipient` | 最初のテストメールを受け取る自分のアドレス。 |
| `labelName` | Gmail上の正確なラベル名。初期値は `未対応`。 |
| `overdueDays` | 何日たったら知らせるか。初期値は5。 |
| `triggerHour` | 何時ごろに送るか。初期値は9。 |

この段階では `enabled: false` のままにしておきます。通知先（部員のアドレス）はここには書かず、手順5の設定画面で登録します。

### 3. 抽出結果を確認する（送信しない）

1. 関数の一覧から `previewOverdueThreads` を選び、「実行」を押します。
2. 初回だけGoogleの権限確認が出ます。報道部アカウントを選び、内容を確かめて許可します。「このアプリは Google で確認されていません」と出た場合は、「詳細」→「（プロジェクト名）に移動」で進めます。自分たちで作ったスクリプトなので、この表示が出るのは正常です。
3. 「実行ログ」に、意図したスレッドだけが出ていることを確かめます。

### 4. 自分だけにテスト送信する

1. `testRecipient` が自分のアドレスになっていることを確かめます。
2. `sendTestNotification` を実行します。
3. 自分の受信箱で、件名、表、リンクを確かめます。

対象が0件のときは、表示確認用のダミー1件が入ります。テスト送信は、本番の「今日送ったか」の記録には残りません。

### 5. 通知先を登録する（設定画面）

通知先は、ブラウザで開く「通知先の設定」画面で追加・削除します。コードを書き換える必要はありません。

1. エディタ右上の「デプロイ」→「新しいデプロイ」を押します。
2. 「種類の選択」の歯車から「ウェブアプリ」を選びます。
3. 「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「自分のみ」にして「デプロイ」を押します。必ず「自分のみ」にしてください。共有アカウントでログインしている人しか開けなくなります。
4. 表示された「ウェブアプリのURL」を開きます。共有アカウントのブラウザでブックマークしておくと、次からはそこから開けます。
5. 入力欄に部員のアドレスを貼り付けて「追加」を押します。改行やカンマで区切れば、まとめて追加できます。外すときは、一覧の「削除」を押します。

形式が正しくないアドレスは追加されず、入力欄に残ります。通知先は50件までです。

コードを貼り替えて更新しても、登録済みの通知先は消えません（スクリプト プロパティに保存されているため）。画面の見た目まで更新に合わせたいときは、「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新バージョン」で、同じURLのまま更新します。

### 6. 本番通知を有効にする

1. `enabled: false` を `enabled: true` に変えて保存します。
2. `notifyOverdueThreads` を手動で1回実行し、本番の宛先に届くことを確かめます。
3. `installDailyTrigger` を実行します。何度実行してもトリガーは1本だけになります。

以後、毎日9時ごろに自動で確認されます。Apps Scriptの仕様上、実際の実行時刻は9時台のどこかに前後します。

同じ日に通知が2回動いても、その日すでに送った人には送りません。そのため、9時より前に手動で本番を実行した日は、その日の自動通知は送られません。

## 停止方法

- 一時停止は、`enabled` を `false` にします（本番の関数が送らずに止まります）。
- 自動実行をやめるには、`removeDailyTrigger` を実行します。
- 完全にやめるには、Apps Scriptプロジェクトを削除します。

## うまくいかないとき

| 実行ログのメッセージ | 対処 |
|---|---|
| `… に実際のメールアドレスを設定してください` | `REPLACE_WITH_` が残っているか、アドレスの形が正しくありません。 |
| `Gmailラベル「未対応」が見つかりません` | Gmailのラベル名と `labelName` を完全一致で確かめます。 |
| `このスクリプトを実行しているアカウント（…）が mailboxAddresses にありません` | 共有アカウント以外で開いています。共有アカウントで作り直すか、`mailboxAddresses` に共有アカウントのアドレスが入っているか確かめます。 |
| `通知先が1件も登録されていません` | 手順5の設定画面で通知先を追加します。 |
| `この画面は、スクリプトを作った共有アカウントで…` | 設定画面を共有アカウント以外で開いています。共有アカウントでログインしたブラウザで開きます。 |
| `本日の送信上限が足りません` | Gmailの1日の送信上限（個人アカウントで宛先100件ほど）に当たっています。1通も送っていないので、翌日にまた動きます。 |
| `…件の送信に失敗しました` | 失敗した宛先が書かれています。アドレスを直して `notifyOverdueThreads` をもう一度実行すると、失敗した人にだけ送ります。 |

## 運用ルール案

- 外部から、対応が必要なメールを受け取ったら「未対応」を付ける。
- 返信や処理が終わった人が「未対応」を外す。
- 通知を見た人は、担当者でなくても状況を確かめる。
- 担当が分からなければ、その日のうちに部内で引き取り手を決める。

## 仕様上の補足

- 「5日」は24時間×5で判定します。ちょうど120時間たったものから対象です。
- 外部からの受信が1通もないスレッド（こちらから送っただけのもの）は、最後のメッセージの日時で判定し、通知に「外部からの受信なし」と添えます。
- 確認するスレッドは `maxThreads`（初期値500）が上限です。超えた場合は通知の本文にその旨が書かれます。
- 通知のリンクは、報道部の共有アカウントでGmailにログインしているときに開けます。
- 通知先は、スクリプト プロパティ（`recipients`）に保存します。
- 同じ日の送信記録は、Apps Scriptの「スクリプト プロパティ」（`digestSentLog`）に、日付と送り済みの宛先だけを保存します。

## 開発

Apps Scriptのサービス（GmailApp など）を差し替えたNodeの中で、抽出・送信・トリガーの動きを確かめるテストがあります。実Gmailにはつなぎません。依存パッケージはありません（Node 18以上）。

```bash
node --test test/code.test.js
```

実Gmailでしか確かめられないこと（権限の承認、実際のスレッドでの抽出、メールの見え方、トリガーの実行時刻）は、上の導入手順の3〜6で確かめてください。
